## 本候选纳入的资源边界

- LAN 与 loopback 共用 16 个 HTTP worker 上限；slot 在创建 worker 前取得，额度耗尽时关闭新连接。
- accepted socket 单次 I/O 空闲超时为 30 秒，不限制正常持续传输的总时长。
- `/upload` 与 `/upload/raw` 共用 2 个并发上传 slot；第三个请求返回 HTTP 429 和 `Retry-After: 2`，不排队。
- 上传空间按 Content-Length 做进程内 reservation；reservation 参与后续空间判定，只额外保留一次 10 MiB safety reserve，并在所有退出路径释放。
- Multipart 请求在取得上传 slot 和空间 reservation 前不会读取/解析 `request.forms` / `request.files`。
- 测试明确覆盖第 17 个连接未创建 worker、LAN/loopback 共用配额、停滞头部超时关闭并归还 slot；空间不足、真实 ENOSPC 映射、StorageError、客户端提前断开、session stop 和未捕获异常后，上传 slot / reservation 均可再次取得。
- 持续恶意连接仍可占满 16 个 slot 并暂时影响正常访问。本候选只承诺限制无界资源增长，不宣称可抵御通用 DoS。
- 未替换 Bottle/wsgiref；未改变 HTTP 传输协议、Range、session、grace 或网络信任边界。

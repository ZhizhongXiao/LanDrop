# LanDrop

LanDrop 是一个面向 Windows 11 服务机与浏览器客户机的轻量局域网文件传输工具。它只在用户信任的 `Private` 网络中临时开启服务，让手机或另一台电脑通过浏览器安全地上传和下载文件。

本文统一使用以下称谓：**服务机**是运行 LanDrop 的 Windows 电脑；**客户机**是通过浏览器连接 LanDrop 的手机或另一台电脑；**服务端/客户端**仅用于描述软件与 HTTP 通信角色。

第二阶段包含：

- Bottle 0.13.4 HTTP 应用层；
- 提供下载的目录与保存上传的目录分离；
- 流式写入、1000 MB 默认上限和磁盘空间预检；
- 随机 `.part` 临时文件，完整同步后原子改名；
- 同名文件自动增加 ` (1)`，不静默覆盖；
- Unicode 文件名、Windows 非法字符和保留设备名处理；
- 服务机提供下载目录的越界和目录外符号链接防护；
- 8 位临时配对码和失败次数限制；
- 本地生成的一次性 QR 客户机邀请；手机扫码可打开当前 LAN 地址、自动配对并建立现有浏览器信任，Windows 客户机可直接使用访问地址和备用 8 位码；
- 客户机浏览器保存高熵凭据，服务机只保存 SHA-256 哈希；
- HttpOnly、SameSite Cookie 与上传 CSRF 校验；
- 浏览器默认使用原始请求体进行真正的网络流式上传并显示实时进度；multipart 接口仅作为无脚本兼容回退；
- 客户机浏览器自行取消信任，以及服务机列出和撤销信任。

第三阶段桌面窗口基础包含：

- 原生 Windows 文件夹选择器；
- 提供下载的目录、保存上传的目录和单文件上限配置；
- 非阻塞启动、停止与重复启动保护；
- 客户机访问地址、接口类别与配对信息显示；
- 原第三阶段关闭桌面窗口时停止服务并关闭端口；该历史行为已在第五阶段替换为关闭到托盘。

第四阶段当前包含：

- 默认 5 分钟会话和 GUI 秒级倒计时；
- 点击“重置为 5 分钟”后从当前时刻重新计算截止时间；
- 到期拒绝新请求，活动传输最多获得 60 秒宽限；
- 新设备配对成功后立即轮换单次配对码；粘贴时自动清理空格和非数字字符；
- QR 邀请与 8 位码共用同一个 pairing revision 和提交事务；任一方式成功后两者同时轮换，错误凭据不轮换；
- 配对时可填写客户机名称；服务机桌面窗口以设备类型、系统和浏览器等易读信息列出并撤销可信客户机，型号、内核和完整标识收纳在可展开详情中；服务启动后的前 1 分钟每 5 秒自动刷新列表；
- 睡眠恢复后安全终止当前会话；
- 上传、下载成功/失败分类以及十进制 `MB / MB/s` 统计；文件任务与浏览器并行下载请求流分别计数，成功任务中的冗余断开流归为浏览器取消而非失败；
- `%LOCALAPPDATA%\LanDrop\logs\sessions.jsonl` 隐私化轮转会话日志。
- 下载服务支持标准 HTTP Range；是否继续未完成下载由浏览器下载管理器决定。

第五阶段当前包含：

- 点击窗口 X 只隐藏主窗口；服务、活动传输、会话与 TCP 8000 保持不变；
- 托盘提供打开窗口、只读状态、重置为 5 分钟、停止服务和退出 LanDrop；
- 即将到期通知提供重置、立即关闭和打开窗口；自动到期后发送无按钮的关闭通知；
- Toast 与托盘共用 `ActionCoordinator`，底层服务仍只由 `ServiceController` 控制；
- 每条状态修改通知携带 `session_id + deadline_revision`，旧会话和旧倒计时通知不能控制当前服务；
- 应用启动、状态变更与退出时清理失效通知；托盘不可用时关闭窗口会安全退出，不会留下无法找回的后台进程；
- 托盘“退出 LanDrop”统一停止服务、释放端口、清理通知并记录 `app_exit`。


第六阶段当前实现（已验收）：

- 启动服务时完整检测网络并冻结本次进程内 session 的 `InterfaceIndex + IPv4 + NetworkCategory` endpoint 基线；接口别名只用于显示，重启服务后重新检测。
- 运行中使用独立轻量 endpoint checker，优先复用原生 IP Helper 地址表，不直接复用会启动 PowerShell 的完整 `discover_interfaces()`，也不重新选网或扫描防火墙。
- 当前 endpoint 仍有效时，即使新增或改变其他 WLAN/Ethernet/TUN 也不影响服务；查询失败或接口/地址疑似短暂缺失时二次确认，明确转为 Public 时立即以 `network_changed` 停止，不做热迁移。
- DNS、SSID、默认网关和 route metric 仅作为诊断信息，不直接停服。
- 防火墙采用异步或短超时的分层诊断，不进入同步启动硬路径；“检测中”“无法确定”和“未发现明确 allow”都不阻止已经确认的 Private endpoint 启动。
- 网络变化自动停服后先刷新托盘，再发送无按钮通知；点击正文只打开现有 GUI，不重启或迁移服务。
- GUI 方向为“主控 / 信息 / 设置”三页；设置页只提供诊断、重新检测/重试及 Windows 网络、防火墙、代理等官方入口。
- 主控页使用较易理解的“监听网络”选择；同时显示 Windows 接口名称、网络配置文件名称、IPv4 和类别，帮助区分同时连接的 WLAN/Ethernet 并辅助核对客户机是否接入同一网络。只列出可作为实际 LAN 的 WLAN/Ethernet，Public 或类别未知的实体网络保留但不可选，回环与 TUN/VPN 等排除项移到信息页。只有一个 Private LAN 时可自动选择，WLAN 与 Ethernet 同时为 Private 时由用户明确选择具体 IPv4，启动阶段仍会重新发现并验证，绝不按旧列表静默绑定。
- 浏览器通常无法读取客户机的 Wi-Fi/网络名称，因此该名称只显示服务机一侧。客户机成功连接服务地址已经能够证明当前访问路径可达，主控页不再额外要求或提示人工核对；名称只用于服务机多网络辨认，安全绑定继续以 `InterfaceIndex + IPv4 + NetworkCategory` 为准。
- TUN/VPN 中性展示，存在本身不视为异常。
- Ethernet 正式纳入测试，包括两台 Windows PC 使用 RFC1918 静态 IPv4 且由用户确认 Private 的网线直连，以及 WLAN + Ethernet 共存；无 WAN 路由器 + DHCP + Ethernet 降为可选硬件兼容性补测。Public 仍只做拒绝启动测试，不使用 link-local 地址。
- 性能测试采用 iperf3 → 裸 Python HTTP → LanDrop+curl → 浏览器 → 原始流上传的分层基准；直连实测下载 `86.25 MB/s`、上传 GUI 端到端约 `105 MB/s`，均符合各自方向的 TCP 基线。SMB 仅作为可选 Private LAN 横向参照，不作为功能验收门槛。
- 运行期原生 IPv4 endpoint 检查在开发机上 500 次测量平均约 `2.68 ms/次`，当前冻结为每 3 秒检查地址、每 15 秒低频复核 NetworkCategory；疑似异常在约 0.75 秒后二次确认。
- 网络详细信息与防火墙证据由后台并行执行，统一设 10 秒硬超时；权限不足、查询卡顿或超时时只显示“无法确定”，不会阻塞端口启动。
- IPv4 候选列表中的 `127.0.0.1` 是服务机内部回环地址，只用于服务机本地访问并明确排除为 LAN 候选；无 IPv4 的断开适配器（常见如 Wi-Fi Direct 的“本地连接*”和蓝牙 PAN）不会进入候选列表。LanDrop 只读检测，不会启用、禁用或修改这些适配器。

第七阶段冻结基线：

- `%LOCALAPPDATA%\LanDrop\config.json` 只保存提供下载的目录、保存上传的目录和上传上限；损坏或非法配置会回退到安全默认值，不恢复 session、IPv4、倒计时或配对码。
- 默认收发目录改为 Windows 实际 Downloads Known Folder 下的 `LanDrop\Shared` 与 `LanDrop\Received`，不再依赖源码目录、当前工作目录或 PyInstaller `_internal`。
- 上传仍使用随机 `.part` 临时文件和原子提交；主实例启动时只清理上传保存目录第一层中名称精确匹配、已超过 24 小时的孤立 LanDrop 临时文件。
- 移动 Web UI 支持文件复选、批量下载确认、多文件选择和串行上传队列；单文件下载保持在列表页，仍使用浏览器原生 HTTP、`Content-Disposition` 和 Range，不使用 JS Blob 接管大文件。
- 桌面版增加独立“保存设置”、详细诊断、打开日志文件夹和复制隐私化诊断信息入口；普通运行与异常日志写入 `%LOCALAPPDATA%\LanDrop\logs\application.log`。
- Windows 单实例控制已实现：再次启动会唤起已有窗口并退出新进程，不创建第二套托盘、服务控制器或 TCP 8000 监听。
- 已建立 Python 3.12 x64 + PyInstaller 6.22.3 的 `--onedir` 开发/排错/便携回归基线、spec、构建脚本和无窗口自检；GUI、托盘、Toast、传输和本机路径回归均已通过。第八阶段继续以该 onedir 结构作为正式主程序 payload，并另行构建单文件 Setup/Uninstall。

## 产品边界

- 服务机首先支持 Windows 11；客户机使用手机或另一台电脑的浏览器。
- 仅支持家庭 Wi-Fi、自有手机热点等可信 `Private` 网络。
- 不支持在陌生 `Public` 网络中提供文件传输服务。
- 只访问用户明确选择的提供下载目录和上传保存目录。
- 程序只检测网络与防火墙状态，不自动修改系统配置。
- HTTP 是本阶段在可信 LAN 内的轻量方案，不宣称具备 Public 网络中的抗窃听能力。

## 环境要求

- Windows 11；
- 源码开发与正式构建基线为 Python 3.12 x64；
- Microsoft Edge WebView2 Runtime；
- 当前网络由用户确认为可信 `Private` 网络；
- Windows 防火墙保持开启；首次监听如出现系统提示，由用户自行决定仅允许 `Private` 网络通信。Setup、LanDrop 与 Uninstall 都不主动创建、修改或删除防火墙规则，只检测、解释并提供 Windows 设置入口。

安装依赖：

```powershell
python -m pip install -r requirements.txt
```

## 启动

启动桌面版：

```powershell
python desktop.py
```

首次启动会准备 `Downloads\LanDrop\Shared` 与 `Downloads\LanDrop\Received`。在服务机桌面窗口中可选择其他目录并点击“保存设置”，再启动服务。窗口显示运行状态、客户机访问地址、当前监听网络、一次性二维码和备用 8 位配对码。点击窗口 X 会隐藏到托盘，不会停止服务或活动传输；从托盘选择“打开窗口”可恢复同一个主窗口。只有“停止服务”或“退出 LanDrop”会关闭监听端口，其中退出还会结束托盘进程并清理通知。

命令行版本继续保留。先做只读网络诊断：

```powershell
python app.py --diagnose
```

启动双向传输：

```powershell
python app.py
```

服务固定使用 TCP 8000，并只绑定选中的服务机 LAN IPv4 与 `127.0.0.1`。客户机使用 LAN IPv4 地址，`127.0.0.1` 只供服务机本地访问。控制台会显示本次 8 位配对码；新的客户机浏览器首次访问时需要输入，已信任浏览器会自动识别。按 `Ctrl+C` 停止服务。

## 自定义目录与上传上限

```powershell
python app.py `
    --shared-dir "D:\LanDrop\Shared" `
    --receive-dir "D:\LanDrop\Received" `
    --max-upload-mb 500
```

两个自定义目录必须已经存在。未传入命令行参数时，CLI 会读取与桌面版相同的 `config.json`；命令行显式参数只覆盖本次运行，不自动改写设置。上传上限允许设置为 1 至 10000 MB；默认 1000 MB。这里的 MB 是十进制单位，`1 MB = 1,000,000 byte`。修改目录或上限需要停止后重新启动。

## 构建第七阶段 `--onedir` 回归基线

安装冻结的构建依赖：

```powershell
python -m pip install -r requirements-build.txt
```

使用 Python 3.12 x64 执行：

```powershell
.\scripts\build-portable.ps1 -Python "C:\path\to\python.exe"
```

脚本固定检查 PyInstaller 6.22.3，生成 `dist\LanDrop`，运行无窗口依赖/资源自检，并写入 `build-info.json` 与 EXE SHA-256。该无控制台回归构建不依赖终端；启动与异常诊断写入 `%LOCALAPPDATA%\LanDrop\logs\application.log`。

该目录既是开发、排错、便携路径与兼容性回归基线，也是第八阶段正式安装版主程序 payload 的结构基础。最终用户获得单文件 `LanDrop-Setup.exe`；Setup 将完整 onedir 主程序部署到当前用户固定位置，并建立快捷方式、通知身份、启动项和卸载登记。安装生命周期不主动写入防火墙规则。

自动验证便携目录可移动到含中文和空格的路径，并从非程序工作目录启动：

```powershell
.\scripts\test-portable-paths.ps1
```

脚本只在系统临时目录创建本次测试副本，核对复制前后 EXE 哈希并运行打包自检，结束后清理该副本。它用于本机路径回归，不能替代另一台未安装 Python 的干净 Windows 11 电脑验收。

正常启动默认运行 5 分钟。源码开发验收时可以缩短会话与宽限，例如：

```powershell
python desktop.py --session-seconds 30 --grace-seconds 10
```

这些参数只用于加速测试；不指定时仍使用 300 秒会话和 60 秒传输宽限。

## 管理可信浏览器

列出浏览器：

```powershell
python app.py --trusted-clients
```

撤销一个浏览器：

```powershell
python app.py --forget-trusted <CLIENT_ID>
```

撤销全部浏览器：

```powershell
python app.py --forget-trusted all
```

凭据记录默认保存在 `%LOCALAPPDATA%\LanDrop\credentials.json`。文件中只有令牌哈希，不保存浏览器原始令牌。浏览器也可以在文件页面点击“取消信任此浏览器”。

## 第四阶段人工验收结果

下列项目已于 2026-09-16 在 Windows 11、自有手机热点和手机浏览器环境中通过。自动化部分共 35 项，覆盖会话状态机、旧会话隔离、HTTP Range 聚合、可信客户机、窗口关闭和日志轮转。

先使用短会话启动：

```powershell
python desktop.py --session-seconds 30 --grace-seconds 10
```

1. 启动服务后应从 `00:30` 倒计时，剩余时间不增加或跳回。
2. 等待倒计时下降后点击“重置为 5 分钟”，剩余时间应恢复为 `05:00`，而不是在原时间上累加；服务与手机连接不中断。
3. 使用新浏览器输入当前配对码；成功后 PC 应显示不同的新配对码，旧码不能供第二个新浏览器使用。
4. 不进行传输并等待到期；服务应自动停止，停止原因应为正常到期，TCP 8000 应释放。
5. 再次启动，在到期前开始较大文件传输；到期后新请求应收到 503，已开始的传输进入 10 秒测试宽限。
6. 传输在宽限内完成时，服务应在完成后关闭；超过宽限时应被中断，并统计为 `grace_timeout`。
7. 服务运行时让电脑睡眠再恢复；会话应停止且原因显示为睡眠恢复，不应自动重启。
8. 停止后检查 GUI 的成功、失败、MB 和 MB/s 摘要；并检查 `%LOCALAPPDATA%\LanDrop\logs\sessions.jsonl` 存在对应会话记录。
9. 最后使用不带测试参数的 `python desktop.py`，确认正式倒计时从 `05:00` 开始。

补充验收确认：同一 104.86 MB 文件连续下载两次后，GUI 正确显示 2 个文件任务、209.72 MB、16 条完成请求流和 4 条浏览器取消请求流，没有将冗余请求误报为文件失败，也没有重复累计字节。手机浏览器是否选择断点续传还是重新下载由其下载管理器决定。

## 第五阶段人工验收结果

第五阶段已于 2026-09-17 在 Windows 11、自有手机热点和手机浏览器环境中完成验收：

1. 活动下载期间点击 X，窗口隐藏，下载完整成功，TCP 8000 持续监听。
2. 连续 20 次从托盘恢复并再次隐藏窗口，均恢复同一个窗口、会话和倒计时。
3. 托盘重置、停止与退出均按预期工作；退出后窗口、托盘、进程和 TCP 8000 均关闭，日志记录 `app_exit`。
4. 通知中心的重置、立即关闭与打开窗口动作能够回送当前进程；旧 revision、旧 session 和模拟清理失败均不能改变新状态。
5. 自然到期通知无动作按钮，点击正文只打开当前 GUI；手动停止与应用退出不发送自动关闭通知。
6. 异常退出遗留的通知会在下次启动时清理；托盘初始化失败时，点击 X 会安全退出并释放端口。
7. Private 热点最终实测启动约 `0.396s`、停止约 `0.173s`；此前两个固定约 5 秒的等待已消除。

Windows 已展开的托盘菜单是静态快照：若服务恰在菜单保持展开时自动关闭，需要收起菜单并重新打开才能看到最新状态。该系统行为不影响后台服务、通知或端口状态。

## 安全提醒

- 不要共享桌面、下载目录、用户主目录或整个磁盘。
- 上传完成的用户文件和共享文件不会因取消信任而删除。
- Private 网络与浏览器凭据不能替代 HTTPS；不要在公司、酒店、咖啡店等陌生网络中使用。
- 程序不会自动更改网络类别、代理、VPN 或防火墙规则。

# LanDrop

LanDrop 是一个面向 Windows 11 与 Android 浏览器的轻量局域网文件传输工具。它只在用户信任的 `Private` 网络中临时开启服务，让电脑与手机安全地上传和下载文件。

## 当前状态

- 第一阶段只读下载已通过电脑和手机人工验收。
- 第二阶段 Bottle 双向传输、文件安全处理与浏览器配对已经通过人工验收。
- 第三阶段 pywebview 桌面控制窗口已经实现，并通过人工验收。
- 第四阶段 5 分钟生命周期、倒计时重置、传输宽限、可信设备管理和会话统计已通过开发验收。
- 第五阶段托盘、Windows 通知、旧通知隔离和统一退出已经实现，并通过 Windows 11 实机验收。
- 当前源码版本：`0.5.0`；自动化测试共 43 项。
- 公司等 `Public` 网络仍会拒绝启动。
- 二维码尚未实现；托盘由 `pystray` 提供，Windows 通知由 `Windows-Toasts` 提供。

第二阶段包含：

- Bottle 0.13.4 HTTP 应用层；
- 下载目录与上传接收目录分离；
- 流式写入、1000 MB 默认上限和磁盘空间预检；
- 随机 `.part` 临时文件，完整同步后原子改名；
- 同名文件自动增加 ` (1)`，不静默覆盖；
- Unicode 文件名、Windows 非法字符和保留设备名处理；
- 共享目录越界和目录外符号链接防护；
- 8 位临时配对码和失败次数限制；
- 浏览器保存高熵凭据，电脑只保存 SHA-256 哈希；
- HttpOnly、SameSite Cookie 与上传 CSRF 校验；
- 浏览器自行取消信任，以及 PC 端列出和撤销信任。

第三阶段桌面窗口基础包含：

- 原生 Windows 文件夹选择器；
- 下载目录、上传接收目录和单文件上限配置；
- 非阻塞启动、停止与重复启动保护；
- 手机地址、本机地址、接口类别与配对码显示；
- 一键使用系统浏览器打开传输页面；
- 原第三阶段关闭桌面窗口时停止服务并关闭端口；该历史行为已在第五阶段替换为关闭到托盘。

第四阶段当前包含：

- 默认 5 分钟会话和 GUI 秒级倒计时；
- 点击“重置为 5 分钟”后从当前时刻重新计算截止时间；
- 到期拒绝新请求，活动传输最多获得 60 秒宽限；
- 新设备配对成功后立即轮换单次配对码；粘贴时自动清理空格和非数字字符；
- 配对时可填写设备名称；PC 桌面窗口以设备类型、系统和浏览器等易读信息列出并撤销可信设备，型号、内核和完整标识收纳在可展开详情中；服务启动后的前 1 分钟每 5 秒自动刷新列表；
- 睡眠恢复后安全终止当前会话；
- 上传、下载成功/失败分类以及十进制 `MB / MB/s` 统计；文件任务与浏览器并行下载请求流分别计数，成功任务中的冗余断开流归为浏览器取消而非失败；
- `%LOCALAPPDATA%\LanDrop\logs\sessions.jsonl` 隐私化轮转会话日志。
- 手机下载使用独立状态页；连接中断后保留提示，并允许通过浏览器下载管理器尝试 HTTP Range 续传。

第五阶段当前包含：

- 点击窗口 X 只隐藏主窗口；服务、活动传输、会话与 TCP 8000 保持不变；
- 托盘提供打开窗口、只读状态、重置为 5 分钟、停止服务和退出 LanDrop；
- 即将到期通知提供重置、立即关闭和打开窗口；自动到期后发送无按钮的关闭通知；
- Toast 与托盘共用 `ActionCoordinator`，底层服务仍只由 `ServiceController` 控制；
- 每条状态修改通知携带 `session_id + deadline_revision`，旧会话和旧倒计时通知不能控制当前服务；
- 应用启动、状态变更与退出时清理失效通知；托盘不可用时关闭窗口会安全退出，不会留下无法找回的后台进程；
- 托盘“退出 LanDrop”统一停止服务、释放端口、清理通知并记录 `app_exit`。

## 产品边界

- 首先支持 Windows 11；手机端使用浏览器。
- 仅支持家庭 Wi-Fi、自有手机热点等可信 `Private` 网络。
- 不支持在陌生 `Public` 网络中提供文件传输服务。
- 只访问用户明确选择的共享目录和接收目录。
- 程序只检测网络与防火墙状态，不自动修改系统配置。
- HTTP 是本阶段在可信 LAN 内的轻量方案，不宣称具备 Public 网络中的抗窃听能力。

## 环境要求

- Windows 11；
- Python 3.10 或更高版本；
- 当前网络由用户确认为可信 `Private` 网络；
- Windows 防火墙保持开启，Private/TCP/8000 规则已正确配置。

安装依赖：

```powershell
python -m pip install -r requirements.txt
```

## 启动

启动桌面版：

```powershell
python desktop.py
```

桌面窗口中选择下载目录和上传接收目录，然后点击“启动服务”。窗口显示运行状态、手机访问地址和本次配对码。点击窗口 X 会隐藏到托盘，不会停止服务或活动传输；从托盘选择“打开窗口”可恢复同一个主窗口。只有“停止服务”或“退出 LanDrop”会关闭监听端口，其中退出还会结束托盘进程并清理通知。

命令行版本继续保留。先做只读网络诊断：

```powershell
python app.py --diagnose
```

启动双向传输：

```powershell
python app.py
```

服务固定使用 TCP 8000，并只绑定选中的 LAN IPv4 与 `127.0.0.1`。控制台会显示本次 8 位配对码；新浏览器首次访问时需要输入，已信任浏览器会自动识别。按 `Ctrl+C` 停止服务。

## 自定义目录与上传上限

```powershell
python app.py `
    --shared-dir "D:\LanDrop\Shared" `
    --receive-dir "D:\LanDrop\Received" `
    --max-upload-mb 500
```

两个目录必须已经存在。上传上限允许设置为 1 至 10000 MB；默认 1000 MB。这里的 MB 是十进制单位，`1 MB = 1,000,000 byte`。修改目录或上限需要停止后重新启动。

正常启动默认运行 5 分钟。源码开发验收时可以缩短会话与宽限，例如：

```powershell
python desktop.py --session-seconds 30 --grace-seconds 10
```

这些参数只用于加速测试；不指定时仍使用 300 秒会话和 60 秒传输宽限。

## 管理可信浏览器

列出浏览器：

```powershell
python app.py --trusted-clients
```

撤销一个浏览器：

```powershell
python app.py --forget-trusted <CLIENT_ID>
```

撤销全部浏览器：

```powershell
python app.py --forget-trusted all
```

凭据记录默认保存在 `%LOCALAPPDATA%\LanDrop\credentials.json`。文件中只有令牌哈希，不保存浏览器原始令牌。浏览器也可以在文件页面点击“取消信任此浏览器”。

## 第三阶段人工验收结果

下列项目已于 2026-09-15 在 Windows 11 与手机热点环境中通过：

1. 在自己的 Private 手机热点或家庭 Wi-Fi 中运行 `python desktop.py`。
2. 分别选择下载目录与上传接收目录，确认路径显示正确。
3. 点击“启动服务”，确认窗口不失去响应，并显示 Private 接口、两个地址和 8 位配对码。
4. 手机访问显示的地址，完成一次下载和上传，确认文件进入所选目录。
5. 运行期间确认三个配置输入和目录按钮不可修改，重复点击不会启动第二个服务。
6. 点击“在浏览器中打开”，确认打开本机传输页面。
7. 点击“停止服务”，确认状态与地址清空，手机页面无法继续访问。
8. 连续启动、停止 5 次，确认窗口始终响应且 TCP 8000 能释放并重新监听。
9. （第三、四阶段历史验收）服务运行时直接关闭窗口，确认进程退出且 TCP 8000 不再监听；第五阶段已将该行为替换为“关闭窗口仅隐藏、服务和 TCP 8000 继续运行”。

验收期间发现目录选择结果会被状态轮询恢复为默认值；修复后已确认自定义目录能够保持，并用于实际上传和下载。第三、四阶段中，GUI 直接关窗会释放 TCP 8000；第五阶段起，关窗只隐藏，托盘“退出 LanDrop”承担原来的完整退出职责。

自动化测试：

```powershell
python -m unittest discover -s tests -v
```

测试只使用项目内临时目录、进程内 WSGI 请求和模拟服务器，不监听局域网端口，也不打开 GUI。

## 第四阶段人工验收结果

下列项目已于 2026-09-16 在 Windows 11、自有手机热点和手机浏览器环境中通过。自动化部分共 35 项，覆盖会话状态机、旧会话隔离、HTTP Range 聚合、可信设备、窗口关闭和日志轮转。

先使用短会话启动：

```powershell
python desktop.py --session-seconds 30 --grace-seconds 10
```

1. 启动服务后应从 `00:30` 倒计时，剩余时间不增加或跳回。
2. 等待倒计时下降后点击“重置为 5 分钟”，剩余时间应恢复为 `05:00`，而不是在原时间上累加；服务与手机连接不中断。
3. 使用新浏览器输入当前配对码；成功后 PC 应显示不同的新配对码，旧码不能供第二个新浏览器使用。
4. 不进行传输并等待到期；服务应自动停止，停止原因应为正常到期，TCP 8000 应释放。
5. 再次启动，在到期前开始较大文件传输；到期后新请求应收到 503，已开始的传输进入 10 秒测试宽限。
6. 传输在宽限内完成时，服务应在完成后关闭；超过宽限时应被中断，并统计为 `grace_timeout`。
7. 服务运行时让电脑睡眠再恢复；会话应停止且原因显示为睡眠恢复，不应自动重启。
8. 停止后检查 GUI 的成功、失败、MB 和 MB/s 摘要；并检查 `%LOCALAPPDATA%\LanDrop\logs\sessions.jsonl` 存在对应会话记录。
9. 最后使用不带测试参数的 `python desktop.py`，确认正式倒计时从 `05:00` 开始。

补充验收确认：同一 104.86 MB 文件连续下载两次后，GUI 正确显示 2 个文件任务、209.72 MB、16 条完成请求流和 4 条浏览器取消请求流，没有将冗余请求误报为文件失败，也没有重复累计字节。手机浏览器是否选择断点续传还是重新下载由其下载管理器决定。

## 第五阶段人工验收结果

第五阶段已于 2026-09-17 在 Windows 11、自有手机热点和手机浏览器环境中完成验收：

1. 活动下载期间点击 X，窗口隐藏，下载完整成功，TCP 8000 持续监听。
2. 连续 20 次从托盘恢复并再次隐藏窗口，均恢复同一个窗口、会话和倒计时。
3. 托盘重置、停止与退出均按预期工作；退出后窗口、托盘、进程和 TCP 8000 均关闭，日志记录 `app_exit`。
4. 通知中心的重置、立即关闭与打开窗口动作能够回送当前进程；旧 revision、旧 session 和模拟清理失败均不能改变新状态。
5. 自然到期通知无动作按钮，点击正文只打开当前 GUI；手动停止与应用退出不发送自动关闭通知。
6. 异常退出遗留的通知会在下次启动时清理；托盘初始化失败时，点击 X 会安全退出并释放端口。
7. Private 热点最终实测启动约 `0.396s`、停止约 `0.173s`；此前两个固定约 5 秒的等待已消除。

Windows 已展开的托盘菜单是静态快照：若服务恰在菜单保持展开时自动关闭，需要收起菜单并重新打开才能看到最新状态。该系统行为不影响后台服务、通知或端口状态。

## 安全提醒

- 不要共享桌面、下载目录、用户主目录或整个磁盘。
- 上传完成的用户文件和共享文件不会因取消信任而删除。
- Private 网络与浏览器凭据不能替代 HTTPS；不要在公司、酒店、咖啡店等陌生网络中使用。
- 程序不会自动更改网络类别、代理、VPN 或防火墙规则。

详细设计见 [`docs/plans/LAN_file_transfer_development_plan_revised_v3.md`](docs/plans/LAN_file_transfer_development_plan_revised_v3.md)。
